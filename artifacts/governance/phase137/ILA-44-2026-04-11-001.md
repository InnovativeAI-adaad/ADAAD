## Hard-Class Invariants Added

### DORK-LEDGER-HASH-0 (`dorkllm/state.py`)
`ConversationLedger._hash_entry()` MUST include the `seq` field in its canonical
hash payload, achieving schema parity with `DorkLedgerPersistence`. Cross-layer
hydration (persist→memory) on server restart requires identical hash schemas.
Any divergence is a constitutionally prohibited chain integrity violation.

**Root cause of B-1:** The prior schema `{role, content_digest, timestamp, prev_hash}`
omitted `seq`. `DorkLedgerPersistence` uses `{seq, role, content_digest, timestamp, prev_hash}`.
A fleet restart calling `restore_entry()` with persistence-derived hashes would always
raise `ConversationLedgerViolation` — chain hydration was silently broken.

### DORK-KB-0 (`dorkllm/context.py`)
Every call to `get_relevant_context()` MUST attempt a KB lookup via the retriever
pipeline. KB match outcomes (hit/miss/score) MUST be recorded in the returned context
block for downstream trace logging. Silent KB bypass is constitutionally prohibited.

**Root cause of B-2:** The KB retriever module was imported in `intelligence.py` but
never called from `context.py`. The knowledge base was completely siloed from the LLM
context enrichment pipeline, making all KB content dead weight.

### DORK-FLEET-0 (`app/orchestration/dork_intent_router.py`)
`DORKLivingFleet` MUST be instantiated once per process as a module-level singleton.
Per-call instantiation defeats fleet lifecycle management, watchdog continuity, and
dispatch ledger chain integrity.

**Root cause of B-5:** Each `_dispatch()` call for fleet intents constructed a fresh
`DORKLivingFleet()`, meaning the watchdog never ran, the dispatch ledger was ephemeral,
and provider health history was lost between requests.

## New Optimization Passes

**OPT-007: KB-Grounded Context Enrichment**  
When `retriever.get_kb_matches()` returns a result with score >= 0.35, an
`AUTHORITATIVE KB MATCH` block is prepended to the system prompt before LLM
invocation, grounding the response in deterministic KB content.

**OPT-008: Query Deduplication Cache**  
TTL-based (60s default via `DORK_CACHE_TTL_SEC`) in-process cache with 128-entry
LRU eviction. Identical repeated queries short-circuit the full LLM invocation pipeline.
Configurable via `DORK_CACHE_ENABLED=0` to disable in test environments.
