## Summary

Phase 139 delivers **Canary Mutation Deployment** — the first constitutional
system where high-risk mutation rollout is governed by a mandatory canary window,
Mirror Test consistency check, and auto-rollback, all enforced as hard-class
invariants rather than operational policy.

High-risk mutations (Tier 0) must pass through `open_canary()` before full
rollout. The Mirror Test score is recorded during the canary window and checked
at close. Passing score → auto-promote. Failing score → auto-rollback. Overriding
a rollback requires explicit HUMAN-0 authorisation. Every lifecycle event is
appended to a hash-chained ledger.

Five Hard-class invariants are codified and 30/30 acceptance tests pass.

## Hard-Class Invariants Added

### CMD-GATE-0
High-risk mutations (tier in `HIGH_RISK_TIERS`, currently `{0}`) MUST have an
open canary deployment before `require_canary_for_high_risk()` is called. Missing
canary raises `CMDGateViolation`. Low-risk tiers pass through without check.

### CMD-MIRROR-0
`close_canary()` MUST NOT be called before `record_mirror_result()` has been
invoked for that canary. Missing Mirror Test result raises `CMDMirrorViolation`
with the invariant ID in the message.

### CMD-ROLLBACK-0
When `close_canary()` is called and `mirror_score < mirror_threshold`, the
deployment MUST be automatically set to `ROLLED_BACK`. Promotion of a failed
canary without HUMAN-0 auth is constitutionally prohibited.

### CMD-CHAIN-0
Every lifecycle event (OPENED, SAMPLE_RECORDED, MIRROR_RESULT, PROMOTED,
ROLLED_BACK, HUMAN0_OVERRIDE) MUST be appended to the hash-chained ledger using
the canonical schema `{seq, canary_id, event_type, payload, timestamp, prev_hash}`.
Chain breaks detected by `verify_chain()` raise `CMDChainViolation`.

### CMD-HUMAN0-0
`promote_failed_canary()` — overriding an auto-rollback — requires
`human_auth=True`. Missing authorisation raises `CMDAuthorizationViolation`
with the invariant ID and canary ID in the message.
